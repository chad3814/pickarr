# The browse screens — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Render the replica — per-category lists of media items, each expanding to its releases and their download status, plus the releases nothing matched.

**Architecture:** A four-part IndexedDB index (`['table','value.pluginId','value.updatedAt','id']`) added by a `SCHEMA_VERSION` bump gives exact per-category keyset paging and turns three counts from a full table scan into three range counts. On top of it, four `react-router` routes and a small set of focused components read from the replica only — no network fallback anywhere.

**Tech Stack:** React 19, react-router 7, IndexedDB, `node --test` with happy-dom, Playwright.

**Spec:** `docs/superpowers/specs/2026-09-17-browse-design.md` — read it; this plan argues from it.

## Global Constraints

- **Never the `any` type.** Not in source, not in tests, not behind a cast.
- **No cast to silence a type error.** If a cast seems needed, the types are wrong — say so in your report rather than casting. Testing Library's queries take a type parameter (`screen.getByRole<HTMLButtonElement>('button', …)`); that is the house pattern for reaching `.disabled` and friends.
- **Counts and lists come from the replica only** (spec §1, storage spec §9). No remote fallback, ever. Zero is an answer.
- **The client never reads, stores or forwards a session token.** `credentials: 'same-origin'` and the browser's cookie jar.
- **No URL, path or credential in any message, log or response body.**
- **`/api` never falls through to `index.html`.** Adding client routes must not weaken this.
- **This slice is read-only.** No write endpoint, no Pick button, no mutation of any kind. `POST /api/picks` is the next slice (spec §1).
- `CLAUDE.md`'s testing hazards apply in full. The four that bite here: never hand a live DOM element to `node:assert`; `afterEach(cleanup)` rather than a per-test `cleanup()`; `t.mock.timers` hangs the web run, so spy on real timers; and a test whose expected value is computed by the code under test cannot detect that code changing.

```ts
/**
 * `rangeFor`'s four-part sibling. Same exclusivity rule and same reason: the
 * row that ended the last page is excluded in whichever direction the walk is
 * going, so a page boundary landing inside an `updatedAt` tie neither repeats
 * that row nor skips its siblings.
 */
function pluginRangeFor(
  table: string,
  pluginId: string,
  from: { updatedAt: number; id: number } | undefined,
  direction: 'next' | 'prev',
): IDBKeyRange {
  const low = [table, pluginId, -Infinity, -Infinity];
  const high = [table, pluginId, Infinity, Infinity];
  if (from === undefined) return IDBKeyRange.bound(low, high);
  const at = [table, pluginId, from.updatedAt, from.id];
  return direction === 'next'
    ? IDBKeyRange.bound(at, high, true, false)
    : IDBKeyRange.bound(low, at, false, true);
}

/**
 * One category's rows in modification order. A sibling of {@link listByTable}
 * rather than a flag on it, so which index a call uses is visible where the
 * call is written.
 */
export async function listByTablePlugin(
  db: IDBDatabase,
  table: string,
  pluginId: string,
  opts: ListByTableOptions,
): Promise<readonly StoredRow[]> {
  if (!TABLES_WITH_UPDATED_AT.has(table)) {
    throw new Error(
      `"${table}" projects no updatedAt, so listByTablePlugin cannot list it in modification order (design spec §3.2)`,
    );
  }
  const { from, direction, limit } = opts;
  const index = rowsStore(db).index('by_table_plugin_updated');
  return drain(index.openCursor(pluginRangeFor(table, pluginId, from, direction), direction), limit);
}

/**
 * How many rows one category has, counted by the index rather than read.
 *
 * This replaces reading every `media_item` row to produce three numbers.
 * Tombstones are absent from the index (`db.ts`'s own note on why), so a
 * deleted row leaves the count without this having to filter for it.
 */
export function countByPlugin(db: IDBDatabase, table: string, pluginId: string): Promise<number> {
  const index = rowsStore(db).index('by_table_plugin_updated');
  const req = index.count(pluginRangeFor(table, pluginId, undefined, 'next'));
  return new Promise((resolve, reject) => {
    req.addEventListener('success', () => resolve(req.result), { once: true });
    req.addEventListener('error', () => reject(req.error ?? new Error('indexeddb count failed')), { once: true });
  });
}
```

Then add both to the `Store` interface in `packages/web/src/store/index.ts` and wire them in `createStore` beside `listByTable`:
