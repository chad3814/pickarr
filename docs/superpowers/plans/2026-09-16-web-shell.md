# The Shell Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make Pickarr 2.0 openable in a browser: the host serves the bundle, you sign in, the replica fills, and an image ships that runs all of it.

**Architecture:** A tenth host route serves static files reusing `artwork-route.ts`'s injected-`readFile` shape, with an `index.html` fallback for every unmatched non-`/api` path. `packages/web` is emptied of 1.x and rebuilt as a sign-in form plus a shell whose per-category counts come from the replica. Three adapters (`realFetch`, `idleScheduler`, `webLocksLease`) finally give `createStore` real browser dependencies. Playwright drives a 2.0 harness that boots the host in-process.

**Tech Stack:** TypeScript, `node:http`, React 19, react-router, vite, IndexedDB, Web Locks, Playwright, Docker.

**Spec:** `docs/superpowers/specs/2026-09-16-web-shell-design.md`

## Global Constraints

- **Never the `any` type.** Not in source, not in tests, not behind a cast.
- **No cast to silence a type error.** If a cast seems needed, the types are wrong — say so in the report rather than casting. Two reviews in the previous slice failed a task over exactly this.
- **No URL, path or credential in any message, log or response body.** The host's rule already; the client inherits it. A failed `fetch` must not log a response body, and a static handler must never put a filesystem path in an error.
- **`/api` never falls through to `index.html`** (spec §3). An unmatched `/api` path stays `404 {error: 'unknown route'}`.
- **`realFetch` passes the store's `AbortSignal` through.** The one-minute deadline does nothing otherwise, and an adapter that drops it looks correct in every stubbed test.
- **The client never reads, stores or forwards a session token.** `credentials: 'same-origin'` and the browser's cookie jar, nothing else.
- **Counts come from the replica only** (spec §6). No remote fallback.
- `CLAUDE.md`'s testing hazards apply in full. The three that bite here: never hand a live DOM element to `node:assert`; `afterEach(cleanup)` rather than a per-test `cleanup()`; and never assert a value the code under test computed.

## Self-Review

**Spec coverage.** §1.3 → task 3. §2 facts inform every task. §3 → task 1. §4 → task 5. §5 → task 4. §6 → task 6. §6.5 → task 7. §7 items 1–2 → task 4; 3–6 → task 1; 7 → task 2; 8–9 → tasks 5 and 6; 10–14 → task 8. Nothing unclaimed.

**Interfaces.** `webRoot` is produced in task 1 and consumed by task 7's image layout. `SyncFetch`/`Schedule` come from the merged `store/sync.ts`; task 4 implements them and task 6 passes them. `session.ts` is produced in task 5 and consumed in task 6. The harness in task 8 depends on tasks 1, 5 and 6 all being present — it is last for that reason, not by preference.

**Ordering hazard, stated.** Task 3 deletes the 1.x e2e suite, and task 8 writes its replacement. **Between them there is no browser coverage at all.** That is unavoidable — the old specs cannot pass against the new UI — but it means a defect landing in tasks 4–7 has no end-to-end net under it until task 8. Review those four on the assumption that nothing downstream will catch what they miss.

**Known gap, deliberate.** Nothing here tests the image beyond one hand-run build, and nothing tests the host's static route through a real browser except task 8's first spec. A malformed `Content-Type` on an asset would pass task 1's unit tests and show up as a blank page.
