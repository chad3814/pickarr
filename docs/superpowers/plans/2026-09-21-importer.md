# Importing a finished download — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use
> superpowers:subagent-driven-development to implement this plan
> task-by-task.

**Goal:** Close #96. A pick downloads, the host maps the path and hands
the file to its plugin, and the plugin logs a line. Put the file in the
library instead.

**Architecture:** `DownloadedFile` gains the ids the host already
holds; each plugin declares its own tokens; a host table stores a root,
a shape and an unmatched directory per plugin; a settings section
edits them; each plugin's `onDownloadedFile` resolves its shape and
copies.

**Tech Stack:** node:sqlite, node:test, node:fs/promises, React 19,
Testing Library, Playwright.

**Spec:** `docs/superpowers/specs/2026-09-21-importer-design.md`

## Global Constraints

- **Never the `any` type.** Not in source, not in tests, not behind a
  cast. The last four slices shipped cast-free.
- **No cast to silence a type error** — say so in your report instead.
- **Copy, never move or hardlink.** Nothing is removed from a download
  client, and nothing already in the library is moved, renamed or
  deleted.
- **No path, url or credential in any log line, message or response
  body.** `last_error` is served by `/api/downloads` as
  `DownloadRead.lastError` — measured last slice, and the reason that
  rule exists in that file.
- **A refusal is distinguishable without parsing prose.** Codes in
  `@pickarr/contract`; the client owns every sentence a human reads.
- **Lists come from the replica only.**
- Prefer the async form of an API over its synchronous twin — `fs.promises`,
  never `fs.*Sync`. An importer is on a job's path and blocks the loop.
- `afterEach(cleanup)`; never hand a live DOM element to `node:assert`.

### Five warnings this repo has earned

**A quoted measurement is a claim exactly like a quoted reason.** Both

**A comment can be contradicted by another comment** rather than by
code — twice last slice, once inside a single docblock.

**A measured number is true only of the tree it was measured against.**
Last slice a count went stale inside its own fix wave.

### Verification standard

**Every test verified by mutation, not inspection.** A mutant that
makes code *crash* proves nothing — wrong but runnable. Restore by
checksum-verified copy-aside (`cp` aside, `cp` back, `shasum -a 256
-c`), never `git checkout`/`restore`/`stash`/`clean`.

**Never touch a real library path in a test.** Every filesystem test
uses a temporary directory it creates and removes.

### The gate

Each step **separately, branching on its exit code**. Never pipe a gate
command into a grep for a count.

```bash
for s in lint typecheck test-hygiene build; do
  if npm run "$s" > /tmp/g-$s.txt 2>&1; then echo "PASS $s"; else echo "FAIL $s"; fi
done
```

Then `npm run test:server`, `npm run test:web`, `npm run e2e`
separately.

## Task 1: The two ids, and a plugin's declared tokens

**Files:** `contract/src/plugin.ts`, `host/src/clients/deliver.ts`,
the four `plugin-*` packages, tests.

**Read first:** `deliver.ts`'s module docblock — the five numbered
steps, and why a throw at any of them leaves the row `completed`.

- [ ] **Step 1: Write the failing tests**

1. `DownloadedFile` carries `rssItemId` and `mediaItemId: number | null`,
   and `deliverCompleted` passes the values it already holds —

2. An rss item with **no** media item delivers `mediaItemId: null`, not

3. `MediaPlugin` carries `tokens: readonly string[]`, and each of the

- [ ] **Step 2: Implement, then mutation-test**

Pass `row.id` where `row.rssItemId` belongs → test 1 reds. Give two
plugins the same token list → test 3 reds.

- [ ] **Step 3: Gate and commit**

## Task 2: The destinations table, and the routes

**Files:** `db/migrate.ts` (**migration 20**; 19 is the highest),
`contract/src/destinations.ts` (new), `host/src/media/destinations.ts`
(new), `host.ts`, `api/server.ts`, `main.ts`, tests.

**Read first:** `clients/mappings.ts` and its three routes — your
closest sibling, and the source of the shape for refusals-as-values,
`PATCH`/`DELETE` by segment index, and catching a constraint violation
rather than pre-checking.

**One row per plugin:** `plugin_id`, `root`, `shape`, `unmatched_dir`.
`unmatched_dir` defaults to `_unmatched`. Synced to the replica.

Routes: `PUT /api/destinations/:pluginId` (upsert — a plugin either has
a destination or does not, so there is no create/update distinction
worth two routes).

- [ ] **Step 1: Write the failing tests**

Refusals: `unknown-plugin`, `unknown-token`, `empty-path`,
`escaping-path`, `not-absolute-root`.

1. A shape whose tokens are all declared by **that plugin** is
   accepted; one naming a token declared by a *different* plugin is
   refused `unknown-token`, naming it. This pair is the point — a
   validator that accepts any known token anywhere would pass a test
   that only tried nonsense.
2. `unmatched_dir` defaults to `_unmatched` when absent.
3. `unmatched_dir` that is empty, absolute, or contains `..` is
   refused, naming which. Test each separately.
4. A `root` that is not absolute is refused.
5. The row reaches the replica with all four columns.

- [ ] **Step 2: Implement, then mutation-test**

Validate tokens against the union of all plugins' lists rather than the
declaring plugin's → test 1 reds. Accept `..` in `unmatched_dir` →
test 3 reds.

- [ ] **Step 3: Gate and commit**

## Task 3: Resolving a shape, and copying

**Files:** `host/src/media/shape.ts` (new — the resolver, host-side and
plugin-agnostic), each `plugin-*`'s `onDownloadedFile`, tests.

The resolver takes a shape and a `Record<string, string | null>` of
resolved token values and returns a relative path, or a refusal. **The
plugin supplies the values** from its own tables; the resolver knows no
schema.

- [ ] **Step 1: Write the failing tests for the resolver**

1. `{series}/Season {season}/{series} - S{season}E{episode}.{ext}`
   with season 2, episode 3 produces
   `Severance/Season 02/Severance - S02E03.mkv` — **zero-padded to two
   digits** (spec §8.2).
2. A token resolving to `null` produces **no empty segment and no
   literal `{token}`** (spec §8.8). Decide what it does produce, state
   it in the docblock, and pin it.
3. A resolved value containing `/` or `..` is refused — a provider's
   title is untrusted input, and `AC/DC` is a real series name.
4. A resolved path escaping the root is refused **before** any copy.
5. Path separators are correct on the host's platform, and a value is
   not silently rewritten by `node:path` — read `clients/paths.ts`'s
   docblock on why it refuses `node:path` for *foreign* paths, and note
   that these are **local** ones, so the reasoning does not transfer.
   Say which applies here and why.

- [ ] **Step 2: Write the failing tests for the copy**

6. The copy is **atomic**: a temporary in the destination directory,
   then a rename. Simulate a failure mid-copy and assert **no file at
   the final path**.
7. A destination that already exists is refused, the row stays
   `completed`, and nothing at the destination changes.
8. A missing destination root is refused and **not created**.
9. An unmatched release lands in `<root>/<unmatched>/<filename>`.
10. The source file is **still there** afterwards, unchanged.

- [ ] **Step 3: Implement, then mutation-test**

Copy straight to the final name → test 6 reds. Interpolate a null token
as the empty string → test 2 reds. Accept `/` in a resolved value →
test 3 reds.

- [ ] **Step 4: Gate and commit**

## Task 4: The settings section

**Files:** `web/src/settings/Destinations.tsx`,
`useDestinations.ts`, `postDestination.ts` (new),
`settings/Settings.tsx`, tests.

**Read first:** `settings/ClientMappings.tsx` and its `postMapping` —
two details there each cost a fix round, and both are inherited:
**`postDestination` must never throw**, and every control clears its
pending flag in a `finally`.

- [ ] **Step 1: Write the failing tests**

1. One row per plugin, each showing its root, shape and unmatched
   directory, read from the replica.
2. **The available tokens are listed per plugin**, from the plugin's
   own declaration rather than a copy — so the list cannot drift from
   what resolves. Assert that the tv row lists `{season}` and the movie
   row does not.
3. Saving an unknown token shows that refusal's own sentence, naming
   the token.
4. Each refusal reads as its own sentence; an unrecognised code and an
   offline submit read differently again.
5. **The error is legible** — assert `screen.getByText(...)`, never the
   accessible name.
6. Every control re-enables after every outcome, including a rejecting
   `submit`.
7. Editing one plugin's row leaves the others alone.

- [ ] **Step 2: Implement, then mutation-test**

Collapse every refusal to one sentence → test 4 reds. Error text →
`aria-label` on an empty element → test 5 reds **alone**, in isolation.
Share one pending flag → test 7 reds.

- [ ] **Step 3: Gate and commit**
