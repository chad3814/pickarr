# Live Push Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A change on the host reaches the browser in under a second over a server-sent-events stream, an idle tab polls every 30 s instead of every 3 s, and a browse card re-renders when a plugin row it shows is updated or deleted (#105).

**Architecture:** The sync triggers call a SQLite function the host registers on every connection; the host's listener coalesces calls per event-loop turn into one nudge (`cursor`, `generation`) published to every open `GET /api/sync/events` stream. The leader tab opens one `EventSource`, runs its existing tail fetch on a nudge whose cursor is ahead of its own, and keeps the poll as a 30 s safety net (3 s while the stream is down). For #105, `store/notify.ts` gains a `touched` channel and the plugin-rows read carries row ids, so the hook refetches for an id it holds.

**Tech Stack:** TypeScript (strict, `noUncheckedIndexedAccess`, `exactOptionalPropertyTypes`), `node:sqlite` (`DatabaseSync.function`), `node:http`, `node:test`, React + `@testing-library/react` + `fake-indexeddb` under jsdom, Playwright.

**Spec:** `docs/superpowers/specs/2026-10-01-live-push-design.md`

- Browser cadence: `TAIL_INTERVAL_STREAMING_MS = 30_000`, `TAIL_INTERVAL_POLLING_MS = 3_000`. `TAIL_INTERVAL_MS` is removed.
- Only the leader opens a stream; `stop()` and losing the lease close it.
- `subscribeTouched(table, cb)` fires once per batch with `Changed.touched`'s ids for `table`.
- Nothing about a row travels on the stream; no row contents in a log line.
- No `any`. Narrow instead of casting. Prefer async APIs. A comment must be true of the code beside it (`CLAUDE.md`).
- `CLAUDE.md` web hazards: `afterEach(cleanup)`, never hand a live DOM node to `node:assert`, no `t.mock.timers`.
- Gate: `npm run check` (redirect to a file, read `$?`). Every task ends green. One skipped server test on some machines is expected.
- Commit signing: retry once on a signer error, then `git -c commit.gpgsign=false commit …` and report the SHA as UNSIGNED.

## Review Focus

1. **A proxy that buffers the stream.** Events never arrive, `open` may still fire. The tab must stay correct through the 30 s poll. Test in Task 3 (stream open, no events → the tail is scheduled at 30 000).
2. **A `changed` event before the bootstrap has written `meta`.** Must not throw. Test in Task 3.
3. **Malformed event data** (`not json`, `{}`, a string cursor). Ignored, nothing thrown. Test in Task 3.
4. **A browser or test environment without `EventSource`** (jsdom has none). The real adapter opens nothing and the tab polls at 3 s. Test in Task 3 (`adapters.test.ts`).
5. **A client that disconnects mid-stream.** The registry forgets it and a later publish does not throw. Test in Task 1.

import { openTestDatabase, setSyncChangedListener } from '../../src/db/open.ts';

/**
 * A `ServerResponse` stand-in: records `writeHead` and collects everything
 * written, and can be ended from the client side. Narrow to what
 * `createSyncEvents` touches -- `writeHead`, `write`, `end`, `on('close')`,
 * `destroyed` -- so the test says exactly which parts of a response the hub
 * depends on.
 */
function fakeResponse(): { response: ServerResponse; head: () => { status: number; headers: Record<string, string> } | undefined; body: () => string; disconnect: () => void } {
  const stream = new PassThrough();
  let head: { status: number; headers: Record<string, string> } | undefined;
  let body = '';
  stream.on('data', (chunk: Buffer | string) => { body += chunk.toString(); });
  const response = Object.assign(stream, {
    writeHead(status: number, headers: Record<string, string>) { head = { status, headers }; return response; },
    headersSent: false,
  }) as unknown as ServerResponse;
  return {
    response,
    head: () => head,
    body: () => body,
    disconnect: () => { stream.destroy(); },
  };
}

function harness(opts: { maxStreams?: number } = {}): {
  events: SyncEvents; raw: ReturnType<typeof openTestDatabase>['raw'];
  runDeferred: () => void; heartbeat: () => void;
} {
  const { raw } = openTestDatabase();
  migrateHost(raw);
  raw.exec('CREATE TABLE probe (id INTEGER PRIMARY KEY, v TEXT)');

  const events = createSyncEvents({
    raw,

    timers: { setInterval: (fn) => { tick = fn; return 1; }, clearInterval: () => { tick = undefined; } },

export function setSyncChangedListener(raw: DatabaseSync, listener: (() => void) | undefined): void {
  if (listener === undefined) listeners.delete(raw);

`packages/host/src/sync/events.ts`:

```ts
/**
 * Server-sent events for the sync tail: the host's end of
 * `GET /api/sync/events` (design spec 2026-10-01 §1-2).
 *
 * **A nudge, never a row.** Each event carries the current `sync_log`
 * cursor and the install's generation. A browser whose cursor is behind
 * fetches `GET /api/sync` exactly as it always has; nothing about a row
 * travels here.
 *
 * **Coalesced per event-loop turn.** `notify` is called by the sync
 * triggers through `pickarr_sync_changed()`, once per logged row and inside
 * the writing statement. It sets a flag and defers one `publish` with
 * `deps.defer` (`setImmediate` in production). `node:sqlite` is synchronous,
 * so a statement or an await-free transaction has committed before that
 * turn runs, and the cursor read then is the committed one. A transaction
 * that spans an `await` would publish early; the browser then reads what
 * is committed and gets the rest on its fallback poll. No write path does
 * that today.
 *
 * **Bounded.** `maxStreams` open responses; the next is answered 503 so the
 * browser falls back to polling and `EventSource` retries later.
 */
import type { ServerResponse } from 'node:http';
import type { DatabaseSync } from 'node:sqlite';

export interface SyncEventsDeps { /* as in Interfaces above, with the docblocks */ }
export interface SyncEvents { /* as in Interfaces above */ }

const DEFAULT_MAX_STREAMS = 32;
const DEFAULT_HEARTBEAT_MS = 25_000;

function topOfLog(raw: DatabaseSync): number {
  const row = raw.prepare('SELECT coalesce(max(id), 0) AS top FROM sync_log').get();
  const top = row?.['top'];
  return typeof top === 'number' ? top : 0;
}

export function createSyncEvents(deps: SyncEventsDeps): SyncEvents {
  const maxStreams = deps.maxStreams ?? DEFAULT_MAX_STREAMS;
  const streams = new Set<ServerResponse>();
  let pending = false;
  let closed = false;

  function send(response: ServerResponse, chunk: string): void {
    try {
      response.write(chunk);
    } catch {
      streams.delete(response);
    }
  }

  function changedEvent(): string {
    return `event: changed\ndata: ${JSON.stringify({ cursor: topOfLog(deps.raw), generation: deps.generation })}\n\n`;
  }

  function publish(): void {
    pending = false;
    if (closed) return;
    const event = changedEvent();
    for (const response of [...streams]) send(response, event);
  }

  const heartbeat = deps.timers.setInterval(() => {
    for (const response of [...streams]) send(response, ': keep-alive\n\n');
  }, deps.heartbeatMs ?? DEFAULT_HEARTBEAT_MS);

  return {
    notify() {
      if (pending || closed) return;
      pending = true;
      deps.defer(publish);
    },
    attach(response) {
      if (closed || streams.size >= maxStreams) {
        response.writeHead(503, { 'content-type': 'application/json' });
        response.end(JSON.stringify({ error: 'too many event streams' }));
        return;
      }
      response.writeHead(200, {
        'content-type': 'text/event-stream',
        'cache-control': 'no-cache',
        connection: 'keep-alive',
      });
      streams.add(response);
      response.on('close', () => { streams.delete(response); });
      send(response, changedEvent());
    },
    get openStreams() { return streams.size; },
    close() {
      closed = true;
      deps.timers.clearInterval(heartbeat);
      for (const response of [...streams]) response.end();
      streams.clear();
    },
  };
}
```
